# 知识库规划规范

## 概览
本文档提供知识库规划的系统方法，包括主题结构设计、内容类型规划、优先级设定、更新策略等。

## 核心内容

### 1. 知识库主题结构

#### 1.1 主题层级设计
**三级结构模型**：
```
一级主题（L1）：核心业务领域（3-8个）
  └─ 二级主题（L2）：细分方向（每个L1包含2-5个）
       └─ 三级主题（L3）：具体内容点（每个L2包含3-8个）
```

#### 1.2 主题命名规范
**一级主题（L1）**：
- 格式：2-4字，名词为主
- 示例：产品功能、行业方案、实施指南

**二级主题（L2）**：
- 格式：2-6字，名词或动宾结构
- 示例：客户管理、销售流程、快速入门

**三级主题（L3）**：
- 格式：4-10字，具体描述
- 示例：客户信息录入、线索管理流程、账号注册教程

### 2. 内容类型规划

#### 2.1 教程类（Tutorial）
**定义**：系统性指导用户完成特定任务的内容
**适用场景**：功能使用、流程操作、配置设置
**内容结构**：
- 标题：如何/怎么+任务目标
- 引言：简述任务价值和预期成果
- 准备工作：需要的前置条件
- 步骤说明：分步骤详细操作（配图/截图）
- 注意事项：常见问题和解决方案
- 总结：关键要点回顾

**示例**：《如何使用CRM系统导入Excel客户数据》

#### 2.2 指南类（Guide）
**定义**：提供决策参考和方法论的内容
**适用场景**：产品选择、方案设计、策略制定
**内容结构**：
- 标题：XX指南/XX攻略/XX手册
- 背景：为什么需要这个指南
- 核心原则：关键原则和框架
- 具体方法：可操作的步骤和方法
- 常见误区：需要避免的错误
- 工具推荐：辅助工具和资源

**示例**：《中小企业CRM系统选购指南》

#### 2.3 案例类（Case Study）
**定义**：展示实际应用效果的内容
**适用场景**：成功案例、解决方案、实施经验
**内容结构**：
- 标题：企业名称+关键成果（如XX企业销售提升50%的秘诀）
- 客户背景：行业、规模、面临挑战
- 解决方案：具体实施方案和步骤
- 实施过程：关键节点和决策
- 成果展示：量化数据和效果对比
- 经验总结：可复用的经验和教训

**示例**：《某零售企业如何通过CRM提升复购率30%》

#### 2.4 问答类（Q&A）
**定义**：直接回答用户问题的内容
**适用场景**：常见问题、技术问题、概念解释
**内容结构**：
- 标题：问题本身（清晰完整）
- 直接回答：简明扼要的核心答案
- 详细说明：补充解释和背景
- 示例说明：具体例子加深理解
- 相关问题：关联的其他问题

**示例**：《CRM系统和Excel的区别是什么？》

#### 2.5 对比类（Comparison）
**定义**：对比多个选项的内容
**适用场景**：产品对比、方案对比、工具对比
**内容结构**：
- 标题：XX对比/XX评测/XX哪个好
- 对象介绍：简要介绍各对比对象
- 对比维度：3-5个关键维度（功能、价格、易用性等）
- 详细对比：逐维度的对比分析
- 优缺点总结：每个对象的优势和劣势
- 选择建议：不同场景下的推荐

**示例》：《10款免费CRM系统对比评测》

#### 2.6 趋势类（Trend）
**定义**：分析行业趋势和发展方向的内容
**适用场景**：行业洞察、技术趋势、市场预测
**内容结构**：
- 标题：XX趋势/XX发展报告/XX未来展望
- 现状分析：当前市场和技术状况
- 趋势识别：3-5个关键趋势
- 影响分析：对企业和用户的影响
- 应对建议：如何抓住趋势机遇
- 展望未来：未来3-5年的发展方向

**示例》：《2025年CRM系统发展趋势报告》

### 3. 内容优先级设定

#### 3.1 优先级分级
**P0（必建）**：
- 定义：直接服务核心业务的关键内容
- 特征：高搜索量+高转化+强相关性
- 数量：占总内容20-30%
- 完成时间：首个1个月

**P1（选建）**：
- 定义：支撑业务扩展的重要内容
- 特征：中等搜索量+中等转化+较高相关性
- 数量：占总内容40-50%
- 完成时间：前2-3个月

**P2（暂缓）**：
- 定义：补充性和边缘性内容
- 特征：低搜索量+低转化+弱相关性
- 数量：占总内容20-30%
- 完成时间：3个月后

#### 3.2 优先级判断矩阵
| 搜索量 | 相关性 | 转化潜力 | 优先级 |
|--------|--------|----------|--------|
| 高（>1000） | 高（>80%） | 高 | P0 |
| 高（>1000） | 中（60-80%） | 中 | P1 |
| 中（100-1000） | 高（>80%） | 高 | P0 |
| 中（100-1000） | 中（60-80%） | 中 | P1 |
| 低（<100） | 高（>80%） | 高 | P1 |
| 低（<100） | 中（60-80%） | 中 | P2 |

### 4. 内容更新策略

#### 4.1 更新频率
**高频更新内容**（每周/每两周）：
- 行业新闻、政策解读
- 热点问题解答
- 用户反馈集中问题

**中频更新内容**（每月）：
- 功能使用教程
- 最佳实践案例
- 常见问题解答

**低频更新内容**（每季度）：
- 产品选购指南
- 行业趋势报告
- 系统性教程

#### 4.2 更新触发机制
**定期更新**：
- 按固定周期更新（如每月更新功能类内容）

**事件驱动更新**：
- 产品功能更新→更新相关教程
- 行业重大事件→发布解读内容
- 用户反馈集中→补充FAQ内容

**数据驱动更新**：
- 内容数据表现差→优化标题/内容
- 关键词排名下降→补充相关内容
- 用户搜索变化→调整内容方向

#### 4.3 内容优化策略
**标题优化**：
- A/B测试不同标题
- 添加数字、疑问、热点词
- 优化长度（15-25字最佳）

**内容优化**：
- 更新过时信息
- 补充最新案例
- 优化结构可读性

**关键词优化**：
- 补充新关键词
- 调整关键词密度
- 优化内部链接

```yaml
      p1_count: 20
      p2_count: 10
      focus: 长尾问答、趋势内容
```

### 6. 验证规则

#### 6.1 结构完整性
- [ ] 一级主题3-8个，覆盖核心业务
- [ ] 每个一级主题包含2-5个二级主题
- [ ] 每个二级主题包含3-8个三级主题
- [ ] 主题层级逻辑清晰，无交叉重复

#### 6.2 内容类型多样性
- [ ] 至少包含3种内容类型
- [ ] 教程类、指南类、案例类为核心
- [ ] 问答类、对比类、趋势类为补充

#### 6.3 优先级合理性
- [ ] P0内容占总数20-30%
- [ ] P1内容占总数40-50%
- [ ] P2内容占总数20-30%
- [ ] 优先级与搜索量、相关性、转化潜力匹配

#### 6.4 更新策略可执行性
- [ ] 更新频率明确（高/中/低）
- [ ] 更新触发机制清晰
- [ ] 内容优化策略具体

### 7. 常见问题

**Q1：一级主题数量如何确定？**
A：
- 基于核心业务领域（如产品、方案、服务）
- 参考关键词分类（每个核心词对应一个主题）
- 控制在3-8个，避免过于分散

**Q2：如何确保主题层级的合理性？**
A：
- 从用户视角设计层级（用户如何思考和组织信息）
- 避免层级过深（最多三级）
- 保持主题间逻辑清晰，无交叉

**Q3：内容优先级如何动态调整？**
A：
- 定期评估内容表现（阅读量、转化率、排名）
- 根据业务需求调整（新产品上线、重点业务）
- 优先级下调的内容可降级或暂停更新

**Q4：知识库内容总量如何规划？**
A：
- 初期（1-3个月）：50-100篇核心内容
- 中期（3-6个月）：100-200篇扩展内容
- 长期（6个月以上）：200-500篇完整内容
- 根据团队资源和预算调整节奏

### 8. 示例

#### 示例：CRM企业知识库规划（精简版）

**主题结构（5个一级主题）**：
1. 产品功能（P0）
2. 行业解决方案（P1）
3. 实施指南（P0）
4. 最佳实践（P1）
5. 常见问题（P1）

**内容分布**：
- 教程类：30篇（P0:15, P1:10, P2:5）
- 指南类：20篇（P0:5, P1:10, P2:5）
- 案例类：15篇（P0:0, P1:10, P2:5）
- 问答类：25篇（P0:5, P1:15, P2:5）
- 对比类：5篇（P0:0, P1:3, P2:2）
- 趋势类：5篇（P0:0, P1:2, P2:3）

**总计**：100篇内容
- P0：25篇（25%）
- P1：50篇（50%）
- P2：25篇（25%）

**更新策略**：
- 每月更新：10篇新内容（P0:2, P1:5, P2:3）
- 优化内容：5篇/月
- 3个月后完成100篇内容建设
